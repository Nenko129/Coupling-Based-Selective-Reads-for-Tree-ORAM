# 有限、可执行的投稿实验方案

## 1. 主文只回答三个问题

1. selective read 本身是否省通信：同放置、全读取 vs selective。
2. 加入宿主机制后是否仍有效：宿主全读 vs 宿主 selective；四种机制各一个代表。
3. 收益有何边界：块长、前端占比、非均匀布局、参数与缓存的影响。

不把45篇文献全部变成实验基线，也不把四篇论文之间再做笛卡尔积组合。主图8个配对单元（4类×2种块长），每单元5个独立种子；加两个布局对照单元和四个归因对照臂，共120条新运行。这是24个配置各重复5次，不是120种架构。

## 2. 已冻结的新矩阵

| 组别 | 配置 | 运行数 | 用途 |
|---|---|---:|---|
| M1 | Freecursive-style compressed map；Deferred / Selective；64B、4KiB；5 seeds | 20 | 位置表压缩的组合 |
| M2 | ρ-style front/back；Deferred / Selective；64B、4KiB；5 seeds | 20 | 分流和迁移的组合，总账单 |
| M3 | IR-Alloc depth profile；Deferred / Selective；64B、4KiB；5 seeds | 20 | 异质真实容量的组合 |
| M4 | AB static depth profile；Ring / GC-Ring；64B、4KiB；5 seeds | 20 | 异质 dummy 配置的组合，不省根 |
| A1 | IR、AB 的 full_probe；64B、4KiB；5 seeds | 20 | 与M3/M4共享selective臂，只测新增同放置全读对照 |
| A2 | IR、AB uniform profile；base / selective；64B；5 seeds | 20 | 布局×选择读的2×2，检查组合是否冲突 |

配置见 `formal_plan.json`，每条命令输入单独存于 `specs/formal`。种子101–105，ORAM种子1001–1005；地址与读写随机数独立于 ORAM 随机数。uniform 地址、独立50%写概率。相同配对共用输入trace和payload，核对答案摘要。

所有新臂：关闭 compact header、fusion、省根、small-map 重调与 Z7/A6 重调。统一Z4/A3；位置表编码/认证规则两边一致。IR 的 R=480，AB 的 R=256；不得为了让选择读更快单独给它更多缓存或更小失败预算。

IR/AB：N=4096，L=12，缓存前6层，16KiB完整可信位置表，初始化单列；暖机12288次，测量24576次，分别为1、2个完整公开维护周期。缓存层仍参与逻辑容量证明。两边装载相同人口，不能将N缩小的系统称为原论文完整规模。

IR深度容量为 `[4,4,4,4,4,4,2,2,2,3,3,4,4]`。AB深度dummy为 `[3,3,3,3,3,3,2,2,2,3,4,4,4]`，真实Z固定4，uniform用S=3。AB这个配置是公开静态适配，不是对原论文参数逐项原样复现。

Freecursive / ρ：N=4096，PLB=8；ρ LLC=32、前端容量128、3:1公开frame比例；暖机2048应用请求、测量4096应用请求。前端各产生多少后端时隙由收据报告。不要把4096个应用请求误称为每棵树完整维护周期；它们是固定应用窗口。已有敏感性与公开负载用于说明窗口/命中率影响。

## 3. 旧证据如何用，哪些不再阻塞

| 旧证据 | 新定位 |

| Freecursive 的 PLB/β/块长敏感性、公开trace | 保留为前端交互补充，注明其旧共同header/后端配置；新最小矩阵另画，不混并均值。 |
| ρ 的9种前端比例/缓存配置 | 保留用于验证总收益被前端流量稀释。 |
| IR 的压缩位置表、DWB、整周期与公开尾部补充 | 加强集成证据，放补充表。原失败记录保留；不能删除失败后只挑成功种子。 |
| AB+CB 的 Ring→GC-Ring 约20.24–21.98% | 扩展方向的条件结果，green容量义务未闭合，不作为本轮主安全证明。 |
| DeadQ、hash-only CB 原型 | 保存研究成果，移出本轮投稿必做清单。 |
| IR 本地stash-hit skip反例 | 作为选定适配边界的依据；不再投入修复完整原生IR，除非以后恢复这个主张。 |

无需再做：所有候选交叉组合、SOC3全套移植四次、为了达到20%而筛选负载、拿旧未调优Ring的52.88%代替公平核心比较。

## 4. 统计与结果保存

主指标为**完成应用请求的双向实际序列化字节**；分别保留数据、header、认证、控制、维护、前端/后端、初始化、暖机账单及RPC。TCP/TLS不在当前数据边界。接收的坏数据不计作完成请求。

每种子效果 `1 − B_selective/B_base`，报告配对均值、原始5个效果、两侧绝对bytes/op和run级95% t区间。不把一个长trace切成很多窗口伪造独立重复。5个种子区间半宽>5个百分点或任一侧CV>10%时再追加5对；若出现失败，先保留失败原因并审计，而非自动换种子。

2×2布局表要直接计算 uniform/base、uniform/selective、depth/base、depth/selective。主张是 selective 在 host depth 布局下仍有效，不必要求与单独布局收益相加，更不能预设统计交互为正。

分析器核对配置、同trace、同答案、实际关闭的特性；Free/ρ另核对 remove/admit 序列摘要。raw receipt与源码有SHA256绑定。预实验N128、单种子与正式N4096、5种子分开保存；未完成配对不入效果表，n<5不给正式区间。

## 5. 主文建议只留五张图/表

1. 核心分别调优比较：Path/Deferred/SDE、Ring/GC-Ring/R0，共同预算与定理条件。
2. 核心逐项消融：small map→compact→fusion→retuning，引用已有完整数据。
3. 四类最小组合：8个配对单元，标明受限宿主和64B/4KiB，总bytes/op及节省。
4. 两项归因：IR/AB full_probe 和布局2×2；证明效果并非省根、融合或更大缓存。
5. 成本分解/边界：ρ前后端、Free reset；其余敏感性、公开负载、失败和证明准入放附录。

必要时把3和4合并。核心与组合不是同一任务：一个证明构造的绝对表现，一个证明思想可以带来增量收益。

## 6. 内存、CPU、网络与投稿口径

新组件收据记录CPU秒，但它包括客户端、服务器和答案检查，不能称为客户端CPU收益；同时运行的任务使wall time更不适合当延迟。已有payload+workspace表不是可信峰值，保持该名称。

本轮投稿准备以**通信优化及有限组合**为范围，因此不要求高RTT延迟提升作为结论。若主文仍要声称latency或低峰值内存，应另启下列有独立成本边界的实验，当前不要补一张模型图就声称实测：

- 客户端与服务器进程分离；在同一传输实现下实测0/10/50ms RTT、固定带宽，包含全部递归和维护；至少报告完成请求p50/p95与吞吐，不按bytes比例换算。
- 在客户端区分persistent state、ciphertext集合、decoded payload、写回buffer、认证scratch；用分配生命期或独立进程峰值测量，服务器树存储和trace oracle不得计作可信内存。
- 每项保持相同安全参数、缓存预算和批大小；记录环境和并发情况。原生硬件IPC、ACT次数、网络RPC互不替代。

当前没有把这些未完成测量包装成已准备好的可用延迟/峰值结果。只要正文严格保持带宽主张，它们不阻塞最小组合章节；若改变主张，它们必须升级为投稿前必做项。

## 7. 执行方式

先运行 `tools/preflight.py`，再运行 `src/dispatch.py --suite formal --wait`，最后运行 `tools/analyze_and_freeze.py`（不要再次添加`--freeze`）。同一formal批不要并行启动多个dispatcher。现有dispatcher串行运行，按可用内存等待，源码变化则拒绝继续，失败则停止并保留具名收据。

当前代码、输入计划、16次预实验与边界检查均已具备；正式重复批已经启动。全部120条完成、按声明规则处理追加重复、最终表图与证据清单核对通过后，才可把新组合主图标为最终结果。
