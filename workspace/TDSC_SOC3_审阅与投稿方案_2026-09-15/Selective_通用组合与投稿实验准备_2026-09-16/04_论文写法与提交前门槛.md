# 论文主张、证据和提交门槛

## 主线的调整

以“公开可模拟的选择读 + 覆盖/容量耦合”作为方法层，SDE-Path和R0-Ring作为两个具体高效实例。组合章节展示方法能适配其他机制，而非把每个宿主重建成SOC3。复杂融合和参数调优属于具体实例的工程优化，可以单独证明与消融，不应成为通用接口的定义。

推荐结构：问题与观察 → selective核心条件与归约 → Path/Ring两个实例 → 四类宿主接口 → 核心/组合/归因实验 → 范围和限制。组合章节优先用一张机制表说明每个宿主保留了什么、适配了什么、证明和实验到哪里，不堆四套重复的完整协议。

## 可使用的表述

**方法**：在公开维护历史确定候选桶集合、覆盖不变量成立且新版本标签满足独立性条件时，可将选择读与代表性树状ORAM机制组合。该实例允许为宿主调整布局/后端，不要求继承SOC3的全部机制。

**实现**：我们实现四类受限适配，并对IR/AB另加同放置全读对照。所有新实验关闭融合、紧凑header和省根；新配置清单单独冻结。

**结果**：正式5对收据完成后填入实际区间。小规模预实验仅支持实现可行性；旧含R0或compact配置的数字不直接替换新主图。

**范围**：四类实例验证代表性可组合性，不构成对所有ORAM的通用转换，也不等同于复现四个完整原生系统。

Freecursive/ρ的前端证据还须写明允许公开的长度/时隙/阶段信息：当前验证相对于该泄漏保持后端安全，不能仅凭两臂工作量相同声称任意等长应用序列的端到端强ORAM不可区分。若要去掉这个限定，填充协议及完整长度模拟必须成为新必做项。IR/AB静态组件不依赖这类地址命中前端，是本轮更直接的组合证明对象。

## 不使用的表述及原因

| 表述 | 原因/替代 |
|---|---|
| 优于所有先进ORAM | 未覆盖其他信任、PIR/XOR、并发和硬件成本模型；改为具体已测比较集合。 |
| 除ρ外都超过20% | 现有IR某些64B/端到端口径低于20%；按块长和系统边界报告。 |
| 无改动支持IR/AB | 公开维护/受限放置是选择读实例的适配；IR-Stash、CB/DeadQ没有进入新最小契约。 |
| 四篇原论文都完成安全闭合 | 完成的是指定子机制与接口；不覆盖删除的原机制。 |
| coupling使运行转录相同 | 耦合的是当前真实记录投影，读集合/neutral/count/nonce/认证根可以不同；转录另行模拟。 |
| 高RTT速度更快/内存峰值更低 | 当前仅有带宽和资源口径，不是网络或客户端峰值实测。 |
