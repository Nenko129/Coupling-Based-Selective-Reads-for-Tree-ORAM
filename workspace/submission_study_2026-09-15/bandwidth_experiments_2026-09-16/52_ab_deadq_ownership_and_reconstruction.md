# AB DeadQ：零额外持久槽的可执行所有权契约

本轮将DeadQ推进到独立分配器模型：给出零额外持久数据槽的首次扩张见证，以及原桶重建时不会覆盖借用者的规则。**这是本研究新增的适配候选，不是完整AB实现、加密ORAM运行、容量证书或带宽收益。** 现有ABDF实验没有使用它，原实验和旧失败记录保持不变。

## 1. 原文要求与新增规则分别列出

[AB-ORAM §V-B/C](https://mehrnoosh.net/research/AB-ORAM-HPCA%2723.pdf)给出每层FIFO、公开远端映射、槽位状态、整轮维护后启用扩张，以及队列不足时不扩张的规则。本文保留这些方向；下列联合重建及组件上限是为本项目认证执行补充的设计，不能归称作者原算法。

此前938个计数状态验证的强预留结论仍成立：若要求每个桶随时能**独立**恢复最低容量，同时总物理空间恰好等于全部最低容量之和，就没有首次扩张额度。新契约放弃独立重建要求，允许公开确定的一小组桶联合重建；没有增加持久数据槽。

| 项目 | 本模型的明确规则 |
|---|---|
| 分配对象 | 单个深度上的M个桶，每桶b个固定物理槽；P=M·b |
| 逻辑容量 | 当前为b或b+r；r为公开扩张量 |
| 所有权 | 每个尚未消费的逻辑槽唯一对应一个物理槽；失效映射不拥有物理槽 |
| FIFO | 仅保存无活跃所有者的物理槽和当前generation；长度不超过Q |
| gather | 对调用者已经认证的公开物理home桶按固定槽序收集未入队dead槽；队满跳过，后续可重新收集 |
| 扩张时机 | 至少完成该层一轮公开bit-reversal scheduled访问之后 |
| 扩张失败 | FIFO少于r项或拟产生的关联组件超过K时保持基准容量，不部分授予 |
| 联合重建 | 重建触发桶所在的完整活跃借用组件，不只覆写它的名义原位槽 |
| 提交 | 工作状态不提前公开；最终认证ACK成功后才发布新映射及DeadQ；失败永久停止 |

模型中的generation是物理租用版本，epoch是重建版本，均**不是**SOC3的γ。实际γ推进、nonce分配及密码认证仍须在引擎集成中证明。

## 2. 活跃借用图与重建算法

每个物理槽p有固定的home桶h(p)。若p的活跃所有者是逻辑桶b，就在b与h(p)之间连一条无向边；同桶自环忽略。只计尚未消费的槽。限制每个连通组件最多K个桶。

触发桶b重建时，取其当前完整组件C。执行以下步骤：

1. 暂存并认证C内各逻辑桶仍有效的记录。模型枚举全部尚未消费槽；真实引擎至少必须认证取得其中全部真实记录。
2. 撤销C拥有的旧映射，并移除FIFO中home属于C的项。
3. 每个成员恢复自己的b个原位槽，更新重建epoch及写入generation。
4. 若已完成暖机且FIFO有r项，考察FIFO前r项的供给者组件。只有将触发桶与这些组件连接后仍不超过K，才一次授予r个额外逻辑槽；否则整个扩张回退，FIFO前缀保持不变。
5. 验证并提交完整写入，再发布新所有权与FIFO。fusion还要在同一工作状态中应用虚拟消费，不能在最终ACK之前出借它生成的dead槽。

重建后，原组件内各桶恢复原位映射，旧边被清除，因此扩张检查针对此时的新组件；不能把旧组件规模错误地一直保留，也不能忽略新供给者已经存在的关联。

## 3. 所有权安全论证

### 引理一：组件闭包消除覆盖冲突

设C是完整活跃借用组件，H(C)是其成员的全部原位物理槽。

若p∈H(C)由C外逻辑桶x活跃拥有，则图中h(p)与x相连，违反C的完整组件定义。反之，若C中逻辑桶活跃拥有p而h(p)不在C，也产生跨组件边。因此：**H(C)中的所有活跃所有者都在C内，C的全部活跃槽也都位于H(C)。**

暂存C内记录后，重写H(C)不会覆盖任何C外活跃对象。物理写入前即撤销/重建相应FIFO租用关系，避免随后从队列取出已被原位写回占用的地址。

### 引理二：固定物理空间足以恢复基准容量

H(C)恰好有|C|·b个槽。由引理一，其活跃记录在暂存后可释放这些槽，为每个成员原位重建b个逻辑槽，无需新增持久数据槽。

真实记录保持还要求调用者对每个桶提交不超过真实容量C_b的记录，且C_b≤b。移走的green块、stash入出和scheduled重新放置由外层协议负责。本模型不通过删除真实记录来腾空间，也不证明外层一定满足该容量前提。

扩张只使用FIFO中已无活跃所有者、generation匹配的槽，且每项只出队一次，因此保持活跃映射的单射性。缩小组件的消费操作不会增加组件大小；新扩张经过K上限检查。由此对合法串行操作归纳，可保持所有权、FIFO唯一性和组件大小不变量。

### 引理三：有限联合范围给出暂存上界

完整组件包含至多K个桶，且其活跃物理槽都在|C|·b个原位地址内。因此模型中单次联合重建暂存的未消费槽数不超过K·b，基准物理写入数不超过K·b；再加至多r个扩张槽写入。

这只是记录槽的组合上界。真实实现还要同时计入ciphertext、decoded payload、final-write帧、认证proof、routing metadata和索引，不能把K·b·B直接写成可信峰值内存。公开所有权图也不能不计成本地常驻一个O(P)可信表；部署时需认证的外部反向所有权索引及逐项字节账单。

### 引理四：fusion只能在提交后提供dead槽

工作状态可以先重建再虚拟消费，但所有出借事务串行。新消费产生的FIFO项只存在于该工作状态，直到包含它的全部最终写入ACK通过才发布；后续分配不能在此前看到或使用它。失败后永久停止，不能回滚generation后重新出借。

模型以状态digest代表调用者已经完成的ACK认证边界，并检查旧digest及错误digest被拒绝。**字符串比较不是密码认证实现**；实际认证、nonce唯一性及错误解密顺序尚未在这个新模块中实现。

## 4. 零额外槽的具体见证

两个桶A/B，每桶两个物理槽，共四槽，r=1、K=2：

1. 先完成A/B各一次scheduled重建，尚不扩张。
2. 消费A的两个逻辑槽，空闲物理地址进入FIFO。
3. B重建后借入A的第一个物理槽，B具有三个逻辑槽；物理数据槽仍只有四个。
4. 若只按名义地址重建A，会覆盖B仍活跃的借用槽。新规则将{A,B}作为组件，先暂存B的借用槽，再联合恢复两桶基准容量。

借用槽可以承载真实记录，不能以“额外槽最初是dummy”为由允许原桶覆盖它。checker在符号记录重放中将真实UID放到包括远端槽在内的随机位置，核对重建前后保留集合一致。

| 两桶、b2/r1、K2、Q2 | 1,676个归一化状态、10,860条转移；完整归一化状态图闭合，含2,376条扩张和1,368条连带重建转移 |
| 提交与租用检查 | 9项，包含未提交不发布、错误ACK、旧ACK、过期租用、组件上限、短FIFO、fusion最终提交顺序及队满后重新gather |
| 四桶符号记录重放 | 五个独立种子，各500步，共2,500步；基准b3/r2、K3/Q8 |

归一化状态图保留映射、有效位、活跃所有者、FIFO次序和scheduled位置；覆盖消费、gather、neutral重建及合法scheduled重建。绝对generation值只在每次租用一致性已核查后作重命名。旧消息攻击另测，不能从这个有限图推断所有密码版本的安全。深度上限设为24，但两个遍历队列都自然清空，未触及上限截断。fusion原子动作在内部依次执行重建和消费，空间不变量由上述两个动作闭包保证；发布顺序另外检查。

`ab_deadq_allocator_model.py`是可执行契约。另一个checker独立构造所有权数组和关联图，检查单射、组件大小与FIFO；符号payload oracle不调用任何ORAM或PRF代码。这些结果不构成CB容量尾界或自适应transcript证明。

## 6. 通信代价与后续集成门槛

新机制解决了“首次扩张无法启动”和“原桶重建覆盖借用者”两个分配问题，但引入至多K−1个连带桶的读取/重建，还要更新认证远端映射和反向索引。即使扩张减少early reshuffle，这些新增通信也可能抵消收益；**尚无正带宽结论，不能将现有ABDF约20%–22%套到本机制。**

实际集成必须保持下列接口：

- 从认证后的公开logical bucket/slot访问记录产生dead事件，物理映射绑定tree、logical owner、bucket epoch、physical address及generation。
- 组件发现仅使用公开且认证的所有权/队列信息；不能由真实块数量或payload内容决定额外访问地址。
- 各成员先取得全部必须保留的真实记录，固定公共顺序写回；连带neutral不冒充scheduled推进，γ语义由引擎明确保持。
- 全部映射、动态n/τ、局部认证树、physical索引及ACK实际序列化计费；禁止使用无限可信公共映射表而不计其资源。
- Ring+CB、GC-Ring+CB、R0+CB使用同一物理预算和分配契约，再执行公平的完整重复；原生AB与新增联合规则分开标注。
- 证明公开policy与动态阈值下的逻辑转录仍可模拟，补green迁移/有限stash及异质参数归约。仅“映射是公开后处理”不足以证明反过来影响调度的完整协议。

本轮没有修改正在运行的ABDF、IR、核心或递归实现。旧强预留938状态证据继续保留；这里的结论是新的时序/联合重建规则能获得非零扩张，不是对旧定理的否定，也不是对原生AB论文的攻击。

证据：`results/ab_deadq_allocator_model_checks.json`，包含源PDF、模型与checker哈希、零额外空间执行、两组完整抽象状态图计数、提交检查和符号记录运行。源码和证据可独立复跑；完整加密工件尚未实现。
