# IR-DWB分阶段接口与带宽口径

2026-09-16。本轮新增了实际认证Transfer上的分阶段回写接口及检查。它仍是原始递归位置表上的DWB接口，未完成IR-Alloc、IR-Stash、压缩group counter和原生CPU控制器的整套集成。

## 原文要求与本轮对应

IR-DWB在本来要发dummy的时隙推进候选dirty LLC条目的PosMap或数据回写。原文最多3个路径阶段，候选不再是LRU或被正常驱逐时取消，完成后标clean。原文还区分inclusive LLC与延迟重映射，后者的DWB组合留作未来工作。本轮据此采用inclusive replacement语义。[IR-ORAM，§IV-D](https://mehrnoosh.net/research/IR-ORAM-HPCA%2722.pdf)

本轮实现 `StagedRawMapFront` 与 `StagedWriteback`。候选选择通过可信客户端回调传入，回调核查条目是否仍驻留、仍是合格LRU；地址、数据版本和脏状态每次推进前重查。公开时隙调度器仍属于后续集成，接口自身不虚构CPU周期。

## 完成态不变量

1. 每个数据/map地址恰有一个canonical后端或PLB拥有者。inclusive LLC的数据副本可脏，但后端当前旧版本不会被当作不存在。
2. 已在后端的map/data的父位置表指向其当前leaf。已在PLB的map使用parked leaf，父表指向parked leaf且后端无同地址副本。
3. 每次 `advance` 成功恰好提交一个Transfer时隙。scheduled维护、认证和ACK都包含在这个时隙内。
4. 只有这个时隙的所有写入和ACK验证成功后才允许暂停、返回完成或把LLC条目标clean。
5. 失败是永久停止；不会通过“取消DWB”退回nonce、uid、gamma、cache修改或已认证PosMap阶段。

### 为何不能先更新父表再暂停

若父位置表已写成子块新leaf，而子块仍在旧leaf，正常请求接管时会无法定位子块。因此生成器不会在“父leaf预留”与“对应child的Transfer提交”之间yield。暂停点只有两种：

- PosMap块已经从后端移出并进入PLB，其parked leaf已与父表一致；
- 数据阶段已完成replace，数据fresh remap与缓存父表已一致。

从合法完成态开始，递归先获取父map。父map缺失时，归纳应用上述规则；本层取得old/new leaf后同步完成一个Transfer，并把子map插入PLB。因此每个暂停点维持不变量。若途中发生错误，由fail-stop保证不再暴露后续成功请求。最后数据阶段用 `remove=a, replace=(fresh_leaf,new_payload)` 替换旧canonical版本，而不是append第二份同地址数据。

### 取消、前台抢占与脏版本

取消只关闭尚未执行的阶段，不撤销已经完成的map访问。提前取回的map留在PLB，随后可被普通访问复用或经正常驱逐回到后端。前台访问先取消当前DWB，再按当前已提交PosMap状态执行。

若LLC条目在阶段之间被改写，版本号或payload快照不再匹配，旧DWB取消并保持dirty；新DWB只能回写新版本。最终阶段ACK失败时，哪怕远端可能已接受部分写入，也不把LLC标clean，且后端与前端永久停止。当前接口是串行模型，不提供崩溃恢复或多线程原子性。

## 新增实际检查

证据：`results/dwb_stage_checks.json`。

| 检查 | 覆盖 |
|---|---|
| 完成0/1/2/3阶段后取消或完成 | 6种后端×4种暂停点；每点独立核对唯一所有权，随后驱逐并重新读取map |
| dirty版本改变后重新发起 | 6种后端，确认最后回写的是新值 |
| 前台访问抢占 | 6种后端，已提交map可被继续使用 |
| 无中断对照 | 6种后端，完整通信摘要、分项账单、PRF调用、缓存、top map及t/g与原串行访问相同 |
| 最终阶段主动篡改 | SDE/R0的读取、槽位读取、写ACK共5类，拒绝且不再发I/O，dirty保留 |
| 同状态、同endpoint的一次dummy/数据阶段 | 6种后端，双向字节、RPC、opcode及全部分项相同 |

测试对远端解密仅用于独立所有权oracle，不进入前端选择或性能执行。上述有限检查支持接口实现，不能替代完整组合的安全证明。

## 带宽实验应如何定义分母

固定公开时隙数W、每个时隙相同的公开路径/维护形状和固定长度字段时，总账单是各时隙的序列化账单之和。将一个dummy替换成同形状DWB，并不会删除那个时隙；本轮最后一行检查验证了这个条件下的实际字节相等。因此不能将“dummy比例降低”直接解释为“总字节等比例降低”。

对于相同公开W，只有在进一步证明两边公开路径形状分布相同后，才能据此推导相同的期望总字节。当前6组条件检查不是该分布证明。对于“完成同一批应用请求”为终点的实验，DWB可能减少后续阻塞或改变总时隙数；必须给定应用到达/依赖关系、LLC写策略和调度器，不能从无时间的地址序列推算缩短了多少运行时间。

论文可以报告DWB已占用时隙中的有效回写数、完成/取消比例，以及同一DWB调度下selective替换的字节差。IR-DWB的原文加速比不计入本文带宽节省。后续仍需接入真实选取策略、完整map压缩、IR异质树缓存和IR-Stash状态过程，才能给出完整系统结论。
